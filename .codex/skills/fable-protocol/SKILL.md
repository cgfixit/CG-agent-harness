# Evidence-first investigation

1. Define the outcome, exclusions and evidence required for completion. Test
   the premise before designing a fix.
2. Trace the production entrypoint, configuration, state owner, callers and
   side effects. For research, distinguish listings, fetched passages and
   derived claims. Recheck current authority before trusting carried evidence.
3. Establish a reachable input-to-effect path for a finding or an equivalent
   workload baseline for a performance claim. Reproduce on the current
   revision. Treat memory and review findings as leads. Identify whether the
   failure belongs to the environment, provider or product.
4. For authorized fixes, address the owning cause. Select affected contracts
   with `cgagentharness-invariant-guard` and preserve their refusals.
5. Run changed behavior with `cgagentharness-verify`. Assess outputs and side
   effects against the original scope. Continue independent work around
   blockers and name the exact unresolved requirement.

Match each claim to its evidence:

| Evidence | Claim it supports |
|---|---|
| Build or health response | Compilation or liveness |
| Synthetic provider | Protocol handling |
| Console Chrome, model-driven `/browse`, WKWebView | The specific surface exercised |
| Cross-build or Rosetta | The named build or translated execution |
| Exact-head CI, review and thread state | Each observed check and review status |

Record SHA, artifact identity, commands and outcomes. Label observations,
inferences and unknowns. Keep credentials and operator data out of the record.
Follow `AGENTS.md` for delivery. When asked to monitor, follow the published head
through terminal checks and report review and mergeability separately.
