# Troubleshooting

See [setup](../README.md), [models](MODELS.md) and [coding](CODING_PIPELINE.md).

## 12. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Analytics lacks spend, or completeness is unknown | Build predates ledger or summary-integrity changes | Check the installed source commit against [feature requirements](SPEND_AND_NOTIFICATIONS.md#build-requirements); refresh after upgrading |
| Spend reports partial, unreadable, too large or invalid UTF-8 | One retained ledger generation could not be fully summarized | Preserve the ledger; inspect permissions, corruption and size. [Missing evidence is not zero spend](SPEND_AND_NOTIFICATIONS.md#read-spend-without-mistaking-missing-data-for-zero) |
| A job finished but no webhook arrived | Notifications off, no restart, refused destination, queue overflow or delivery failure | Check **Job webhooks**, `notification_delivery`/`notification_dropped` audit and `/agent job <id>`. Use guarded delivery replay, never rerun the job |
| Webhook receiver reports duplicates | A response was lost and the same batch was retried | Deduplicate stable `delivery_id`; retry batch membership can change. Each delivery/replay has at most three attempts |
| MCP stderr log is absent or diagnostics are short | Bounded pipe capture is active | Expected: 2 KiB retained, ≤512 Unicode diagnostic characters. Inspect child/timeout; [capture limits](PROCESS_LIFECYCLE.md#mcp-stdio-diagnostics) |
| `/prompt`, `/soul edit`, `/skill use` or `/goal stage` is unknown; Clear all session history is absent | Installed build predates those main changes (v0.1.1 and earlier) | Check `/help` and bundle `Resources/COMMIT`; use [Latest](https://github.com/cgfixit/CG-agent-harness/releases/latest) or a successful main Bundle. v0.1.4–v0.1.8 no longer define the feature floor |
| Local coding loop never fetches a file the planner asked for | Cloud planner, clone-jail refusal, `denied_read_basenames` (`.env`, keys, credentials), 6-read cap, or unclosed FILE/EDITS block swallowing `=== READ ===` | Pre-stage ordinary files with `/agent read`. Operator/model READ both refuse sensitive basenames (`sensitive_basename`). Cloud refuses all model READs. Local refusals audit `agentic_real_repo_read_request_refused`. Neither the deny-list nor jail guarantees secret detection. |
| New sessions appear to share old context | Old transcript regression, or shared notes/persona and account web context remain | Check bundle `Resources/COMMIT` for isolation fix `71eef11` and inspect `/prompt`. `/session new` separates history while retaining shared context |
| Chat denies memory exists or claims it can run `gh` | Model output conflicts with the app's capability contract | Inspect `/memory`, `/tools` and `/prompt`; prose cannot execute commands. Check for capability-guide fix `71eef11` |
| `/memory search` reports retrieval disabled | `structured_memory.retrieval` (and the store) are off | Enable the store, restart, then `/memory retrieval on`. Search never injects; `/memory retrieve` selects one prompt |
| `/memory consolidate` is unknown or omitted from `/help` | Installed build predates [PR #94](https://github.com/cgfixit/CG-agent-harness/pull/94) / v0.1.11 | Upgrade to Latest or newer main Bundle; consolidation writes pending proposals only |
| `/memory auto-consolidate` is unknown | Installed build predates [PR #95](https://github.com/cgfixit/CG-agent-harness/pull/95) | Use the latest published release or a newer main Bundle. The gate requires `consolidation` |
| Automatic completion suggestions do not appear | Store/capture/source gate off, invalid mode, queue expiry/full, model/store error, or empty valid output | Inspect `/api/structured-memory` effective `automatic_suggestions`, run status and audit. Check `/memory capture` and `/memory auto-suggest-chat|auto-suggest-coding`; refresh after generation. Completions do not guarantee suggestions |
| `/memory save` reports store closed | `structured_memory.enabled` is false or store failed to open | Enable the store and restart; automatic generation and capture may stay off. A prose request is not a save command |
| `/memory consolidate` or auto-consolidator reports the gate off | `structured_memory.consolidation` (and for auto, also `auto_consolidation`) are off, or the store is closed | Enable the store, restart, then `/memory consolidation on`; auto also needs `/memory auto-consolidate on`. Fresh defaults are on; explicit off choices survive |
| Clear all session history reports a storage error | A session file could not be removed; deletion may be partial | Fix active-home storage access and retry; failure can leave partial deletion |
| Model inventory says `tag_missing`, or fallback is selected unexpectedly | Exact configured ID is absent from a responding inventory | Compare [inventory/config](MODELS.md) and persisted `/model` with the resolved endpoint; restart to reevaluate fallback |
| Soul says missing | No `soul.md` exists in this active home | Valid existing-home state; use `/soul edit` to create persona, then `/soul on` and `/prompt` |
| Soul saved but is not in chat | Toggle off, wrong home or rejected/stale save | Confirm Setup home, `/soul status`, editor result and `/prompt`; reload a stale editor before saving again |
| Persona/proposal save conflicts or history is full | Changed base revision or 32-record limit | Review current content/history; deliberately archive records if needed. Never blindly retry or delete active persona |
| Selected skill prevents chat | Missing, empty, unreadable or unsafe file; wrong directory ID | Restore `<home>/skills/<id>/SKILL.md` or `/skill clear`; inspect `/prompt` |
| `/loop` does not edit the repository | It is chat continuation | Use the explicitly configured goal-to-coding workflow in [goal staging](CODING_PIPELINE.md#94-stage-a-session-goal-as-a-coding-task) |
| Goal task is stale/interrupted/unavailable | Goal changed, job already submitted, restart interrupted work or retention removed job evidence | Inspect `/goal task`, `/agent jobs` and `/agent runs`; never infer approval or replay work from `GOAL_DONE` |
| App asks for Rosetta or shows Intel-only kind | Old app copy, forced translation or separate Intel-only component | Verify the installed universal copy and both executable slices; see [hardware](INSTALL.md#21-hardware-and-macos) before changing the OS |
| `401 Unauthorized` on harness requests | Missing, expired or revoked account session | Sign in again; a fresh bootstrap account must replace its password. A harness key cannot grant access |
| App reports a home ownership conflict | Another app/server owns the same home | Quit that owner normally before retrying; do not delete its lock |
| App waits at startup | File-access mediation, unavailable backend or damaged/moved bundle | Check macOS prompts; quit, move the complete app to Applications and retry; inspect Setup without deleting the home |
| Changing config appears to do nothing | Most startup settings require restart; supported limits need an explicit reload | Use [Reload limits](CONFIG_RELOAD.md) for supported fields; otherwise Cmd-Q/relaunch or restart `serve`. Window close only hides it |
| Offline preparation fails in the app | Missing toolchain, Python/SDK, Cargo.lock, cached sources or an existing snapshot | Inspect Setup and [offline Cargo verification](CODING_PIPELINE.md#offline-cargo-verification); the app does not download dependencies |
| Chat takes too long or times out | Wrong exact model/endpoint, unavailable service, slow loading or inference timeout | Check [inventory](MODELS.md), `/model` and Setup diagnostics; cancel with `/loop stop`. Avoid repeated submissions |
| Header shows **Model · unreachable**, or chat says *Can't reach the model* | Nothing answers at the configured loopback model endpoint | Start the service (`OLLAMA_CONTEXT_LENGTH=32768 ollama serve`) and send again. The chip follows the inventory cache, `models.local_llm.inventory.refresh_sec` (30 s by default) |
| Chat reports `502 HARNESS_LLM_ERROR` with `model server returned HTTP ...` | The local model server returned a non-success HTTP status | Check upstream status, endpoint/model and model-server diagnostics. Harness drops error bodies unread, omits them from debug logs and releases the chat gate without waiting for them |
| `cgagentharness: harness binds loopback only` and the server refuses to start | Non-loopback `--host`, such as `0.0.0.0` | Only loopback is accepted. Omit `--host` or use `127.0.0.1` |
| `Address already in use` when starting `serve` | Another process occupies the standalone port | Use `lsof -i :8790`; stop only the known owner or choose another `--port`. Concurrent servers need separate homes |
| First build/Clippy waits on "downloading components" | `rustup` is fetching the pinned 1.88 toolchain declared in `rust-toolchain.toml` | Let initial download finish; check network access if stalled |
| `gh: command not found` when trying `/agent` commands | GitHub CLI missing; required only for the [optional coding pipeline](CODING_PIPELINE.md) | `brew install gh && gh auth login` |
| `/agent` commands report "Agentic layer disabled" | `agentic.enabled` is still `false` in `config.yaml` | Follow [coding config](CODING_PIPELINE.md#92-edit-the-configuration-file), then restart `serve` |
| A write action is refused | A current policy gate is closed, reason/confirm is absent, publication has no reviewed body, or the emergency switch is set | Re-read [coding console steps](CODING_PIPELINE.md#93-run-it-from-the-console) and [the kill switch](CODING_PIPELINE.md#95-the-kill-switch); check `echo $CGAGENTHARNESS_AGENTIC_WRITE_DISABLE` |
| Managed-key save or legacy migration fails | OS store unavailable, unsafe legacy file, or Windows replacement denied | Keep plaintext opt-in off unless deliberately required. Check [credential privacy and recovery](INSTALL.md#8-persistence-optional-keys-and-recovery); do not broaden file access. Windows sharing locks can block replacement; the existing destination remains intact |
